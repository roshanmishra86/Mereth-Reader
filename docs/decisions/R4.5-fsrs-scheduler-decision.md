# R4.5 FSRS scheduler decision

Date: 2026-08-21

## Decision

Mereth Reader v1 uses a local, deterministic FSRS-4.5 implementation for review scheduling. No network service, account, telemetry, optimizer, or runtime package dependency is used.

The implementation source is `src/utils/fsrsScheduler.ts`. It records `fsrs_version = "FSRS-4.5-mereth-1"` with every schedule row and uses the FSRS-4.5 default parameter vector documented by open-spaced-repetition/fsrs4anki:

```text
[0.4872, 1.4003, 3.7145, 13.8206, 5.1618, 1.2298, 0.8975, 0.031, 1.6474, 0.1367, 1.0461, 2.1072, 0.0793, 0.3246, 1.587, 0.2272, 2.8755]
```

The selected formulas are the FSRS-4.5 DSR model formulas: grades 1-4 map to Again, Hard, Good, Easy; stability is the interval at 90% recall probability; the FSRS-4.5 forgetting curve uses `DECAY = -0.5` and `FACTOR = 19 / 81`; next interval is solved from desired retention. Source: open-spaced-repetition/fsrs4anki "The Algorithm", edited 2025-07-21, retrieved 2026-08-21.

## License and dependency posture

The algorithm is implemented from the public formula description, not vendored code. No fsrs4anki source file is copied into Mereth Reader. This avoids introducing a new scheduler runtime dependency and keeps review events reproducible from exported data.

## Product behavior

- Desired retention defaults to 0.90.
- Hard is treated as successful recall and increases stability less than Good/Easy.
- Again is a failed recall and moves the card to relearning.
- The review UI never grades the user automatically.
- Source excerpt/context stays hidden until the user reveals or skips.
- Review events store the user response, outcome, duration, previous schedule state, and next schedule state so exports can replay scheduling.
