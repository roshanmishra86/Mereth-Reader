# R6.6 — Release Code Signing Architecture & Procedure

## Scope & Policy Decision

- **Owner Decision (2026-08-23)**: Mereth Reader is currently for personal use. EV Code Signing / Authenticode certificates are **waived for v1 personal use**. The CI build workflow creates valid, functional unsigned NSIS setup executables.
- **Purpose of this Document**: Formalize the complete architecture, secrets management, CI configuration, and verification procedures so that organizational code signing can be activated seamlessly if public commercial distribution is pursued.

---

## 1. Signing Architecture (Windows Authenticode)

For Windows distribution without SmartScreen warnings:
1. **Certificate Type**: Extended Validation (EV) Code Signing Certificate, or Microsoft Azure Trusted Signing (formerly Azure Code Signing).
2. **Hardware Security Module (HSM)**: Private keys must be held in FIPS 140-2 Level 2+ hardware (e.g. YubiKey FIPS, Azure Key Vault HSM, DigiCert KeyLocker, or AWS CloudHSM).
3. **Timestamp Authority**: RFC 3161 compliant timestamp server (e.g., `http://timestamp.digicert.com` or `http://timestamp.sectigo.com`) so signatures remain valid after certificate expiry.

## 2. GitHub Actions Integration

When secrets are provisioned, `.github/workflows/windows-build.yml` can be updated with:

```yaml
      - name: Sign NSIS Installer
        if: env.WINDOWS_CERTIFICATE_BASE64 != ""
        env:
          WINDOWS_CERTIFICATE_BASE64: ${{ secrets.WINDOWS_CERTIFICATE_BASE64 }}
          WINDOWS_CERTIFICATE_PASSWORD: ${{ secrets.WINDOWS_CERTIFICATE_PASSWORD }}
        shell: pwsh
        run: |
          $certPath = "$env:TEMP\code_signing.pfx"
          [IO.File]::WriteAllBytes($certPath, [Convert]::FromBase64String($env:WINDOWS_CERTIFICATE_BASE64))
          & "C:\Program Files (x86)\Windows Kits\10\bin\x64\signtool.exe" sign /f $certPath /p $env:WINDOWS_CERTIFICATE_PASSWORD /tr http://timestamp.digicert.com /td sha256 /fd sha256 src-tauri\target\release\bundle\nsis\*.exe
          Remove-Item -Force $certPath
```

Alternatively, for **Azure Trusted Signing**:
- Action: `azure/trusted-signing-action@v0.4.0`
- Secrets: `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`, `AZURE_TENANT_ID`, `AZURE_KEY_VAULT_URI`, `AZURE_CODE_SIGNING_ACCOUNT_NAME`, `AZURE_CERTIFICATE_PROFILE_NAME`.

## 3. Verification Commands

To verify signature validity on Windows:
```cmd
signtool verify /pa /v "src-tauri\target\release\bundle\nsis\Mereth Reader_0.1.0_x64-setup.exe"
```
Check:
- Signer Certificate: Matches organizational subject name.
- Timestamp: Valid RFC 3161 timestamp attached.
- Hash Algorithm: SHA256.
