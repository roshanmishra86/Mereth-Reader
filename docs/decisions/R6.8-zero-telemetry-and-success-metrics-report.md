# R6.8 — Zero-Telemetry Architecture & Success Metrics Report

## 1. Zero-Telemetry Policy & Privacy Mandate

PRD §19 explicitly establishes that product success metrics **do not authorize telemetry**. Mereth Reader operates on a strict zero-telemetry, local-first privacy foundation:
1. **Zero Tracking SDKs**: No Google Analytics, Mixpanel, PostHog, Segment, Datadog, or Sentry are included or imported.
2. **Strict Offline CSP**: Tauri CSP denies remote connections (`connect-src 'self'`).
3. **No Silent Data Egress**: No document text, note contents, annotations, prompts, review history, or behavioural telemetry is ever silently collected or transmitted.
4. **User-Initiated Local Diagnostics**: Any diagnostic package is generated only upon explicit user request, displayed in full for interactive inspection, and kept on the local machine.

## 3. Diagnostic Report Schema & Inspection Guarantee

The user-initiated diagnostic system (`src/utils/diagnosticExport.ts`, `DiagnosticExportModal.tsx`) guarantees:
- **Zero Document / Note Content**: Database storage metrics report only aggregate record counts (`documentCount`, `annotationCount`, `noteCount`).
- **Sanitized System Profile**: Platform, CPU architecture, memory RSS, and active theme.
- **Inspectable JSON / Text**: Rendered inside a modal before saving or copying to clipboard.
