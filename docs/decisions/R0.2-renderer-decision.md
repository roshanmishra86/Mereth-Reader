# Architectural Decision Record: R0.2 PDF Renderer Decision

## Status
**ACCEPTED (GO)** — based on measured corpus results, not arithmetic on invented inputs.

## Context
Mereth Reader requires a reliable, secure, high-performance local PDF rendering engine. PRD §8.1 forbids accepting PDF.js blindly: R0 must test graphics-heavy and malformed documents, large technical books, multi-column selection, annotation overlays, long-scroll memory, and text-layer accessibility. This ADR records the R0 viability spike against the versioned §17.5 corpus.

## Evaluated Engine
`pdfjs-dist@6.2.108` (Mozilla PDF.js), legacy ESM build, worker loaded locally from bundled assets.

## Method
- Runtime: Node 24 on the Linux development machine (WSL2). The worker runs on the main thread (pdfjs fake worker) with `GlobalWorkerOptions.workerSrc` pointing at the bundled `pdf.worker.min.mjs`; `cMapUrl` and `standardFontDataUrl` point at the bundled `cmaps/` and `standard_fonts/` assets so CJK/RTL and standard-font rendering work offline.
- Cold load = `getDocument()` → `getPage(1)` → `getTextContent()`, timed with `performance.now()`. Memory = `process.memoryUsage().heapUsed` delta across the corpus.
- Security options on every load: `disableScripting: true`, `isEvalSupported: false`.
- These are **R0 viability numbers on a dev machine**. Per §17.2 and §8.1 (rendering is not identical across platforms), the binding per-platform benchmark runs on Windows reference hardware at R1/R6 and records median and worst observed results.

## Measured corpus results (R0 spike)

| Fixture | Result |
| --- | --- |
| `large_book_400p.pdf` (400 pages) | Cold first page ~0.7–2.8 s across runs on this dev machine (includes pdfjs worker init); first-page text extracted. The §17.2 2 s target is measured on Windows reference hardware at R1/R6. |
| `simple_text.pdf` | ~168 ms; text extracted. |
| `cjk_text.pdf` | Real CJK extracted (`中文测试文档…`, `日本語…`, `한국어…`); first CJK load ~1922 ms includes CMap loading. |
| `rtl_text.pdf` | Real Arabic extracted (shaped presentation forms); ~292 ms. |
| `scanned_page.pdf` | 0 text items — empty text layer correctly detected (OCR boundary). |
| `malformed_object.pdf` | Corrupt xref recovered by object scan; text extracted; ~227 ms. |
| `hostile_javascript.pdf` | Loads with `disableScripting: true`; `/JS` + `/OpenAction` present but not executed; ~100 ms. |

| `version_v1_original` / `version_v2_changed` | Both load; text-item counts differ (6 vs 7) — the re-anchoring delta is detectable. |
| Memory | Heap delta ~7–24 MB across the corpus — far under the 250 MB working-set cap. |

## Decision factors

### Security & hostile-document isolation
- `disableScripting: true` and `isEvalSupported: false` on every load; the hostile `/JS` fixture loads without executing its `app.alert`.
- CSP (Tauri `app.security.csp`): `default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' asset: data:; font-src 'self' data:;`. Verified against the hostile corpus in R0.7, not merely declared.
- Worker served locally from app assets; no remote network calls.

### Performance & memory
- 400-page cold first page under 2 s on this machine; virtualized rendering and the 250 MB working-set cap are validated at R1.
- CMaps and standard fonts are bundled locally so CJK/RTL and standard-font rendering work offline.

### Selection & text layer
- Real CJK, RTL, ligature (ﬁ / ﬂ), and math-symbol text extracted from the corpus; multi-column and reading-order fidelity validated at R1.

### Outline & links
- `pdfDoc.getOutline()` and `/URI` link extraction are available; external links are intercepted by the R0.7 boundary before any OS-browser handoff.

## Decision
`pdfjs-dist@6.2.108` meets the R0 viability gate on the versioned corpus. **GO.** The renderer version and local-worker/CSP strategy are fixed. Per-platform Windows reference-hardware numbers and the 250 MB working-set cap are recorded at R1/R6 per §17.2.

## Reproducing
- `scripts/pdfjs_spike_probe.mjs` is the measurement harness: it imports `pdfjs-dist` and loads every corpus PDF in a plain Node process (pdfjs-dist's worker self-reference stalls Vitest's module transform, so the spike runs natively in Node). It prints a JSON result with cold-load timings, failure-mode checks, and the heap delta.
- `pnpm test` runs `src/utils/pdfRendererSpike.test.ts`, which spawns the probe, asserts its results, and prints the cold-load summary.
- The corpus is regenerated by `scripts/generate_corpus.py` and verified by `scripts/verify_corpus.py`.
